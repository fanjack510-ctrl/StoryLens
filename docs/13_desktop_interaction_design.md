# Phase 2A 桌面交互设计

## 信息架构

桌面端采用 React、TypeScript、Vite 与 Tauri 2。主导航包含首页、书库、工作台、任务中心、模型中心、案例库和设置。所有业务数据来自 FastAPI；TanStack Query 管理服务端状态，Zustand 仅保存主题、阅读字号、行距和演示模式等本地 UI 状态。

书籍工作台采用三栏布局：左栏显示章节和场景结构，中栏显示带稳定段落 ID 的正文，右栏显示场景结构 Artifact、证据入口和历史上下文。点击“定位证据”后，界面通过 Artifact evidence API 获取段落 ID，再滚动并高亮数据库中的原文，不信任模型返回的原文。

## 核心流程

1. 书库支持点击或拖放 TXT、DOCX、EPUB，上传后展示后端导入状态。
2. 用户在工作台选择章节并打开分析对话框。
3. 对话框明确显示本地/云端执行模式、Provider、模型和内容出境提示；云端模式必须单独勾选同意。
4. 创建 AnalysisRun 后跳转任务中心，页面每五秒轮询；失败 Run 可调用既有 retry API 创建新 Run。
5. 场景和 Artifact 只展示后端真实数据。未实现模块统一标为“规划中”，不伪造分析结果。

## 状态与可访问性

页面统一提供加载、空数据、错误和状态徽标。布局在窄窗口降级为单列；按钮、输入框和表格保持键盘可操作。浅色/深色主题通过 CSS 变量实现。演示模式仅影响 UI 标识，不写入或伪造数据库结果。

## 路由

- `/` 首页
- `/library` 书库
- `/workspace` 工作台入口
- `/books/:bookId` 书籍三栏工作台
- `/tasks` AnalysisRun 任务中心
- `/providers` 模型配置中心
- `/cases` 案例库占位
- `/settings` 桌面与系统设置

## 验证

组件测试覆盖应用壳与路由；Playwright 覆盖导航、书库、模型中心、设置以及截图。浏览器开发模式固定在 `127.0.0.1:1420`，后端 CORS 仅允许本机 Vite 与 Tauri origin。
