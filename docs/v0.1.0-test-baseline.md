# StoryLens v0.1.0 Preview — 测试基线

本文档记录 `fix/v0.1.0-test-baseline` 上的失败分类、修复与发布门槛。  
**不**降低断言标准；可选资产测试以明确 `pytest.skip` / marker 门控，禁止静默跳过。

## 1. 测试总览

| 套件 | 命令 | 基线期望 |
|------|------|----------|
| 后端 Pytest | `.\.venv\Scripts\pytest.exe apps/api/tests -q` | 核心路径全部通过；可选审计/Freeze/Canary 在缺资产时 **显式 skip** |
| 前端 Vitest | `cd apps/desktop; npm run test -- --run` | 全部通过（含 Reader Journey 空状态） |
| 工程检查 | `python scripts/check_project.py` | 通过 |
| 桌面 typecheck/build | `npm run typecheck` / `npm run build` | 通过 |
| Windows smoke | `.\scripts\smoke_windows_release.ps1` | 通过 |

默认自动化使用 Fake Provider，**不**连接真实模型。

## 3. 已修复问题

1. **云端定价 fixture**：`apps/api/tests/optional_gates.py` + `conftest.verified_cloud_pricing`；`phase_1c_a6` connection、`phase_1c_a` / `a7` eligibility / recover 依赖该 fixture。
2. **可选资产门控**：canary / certification / freeze / main-db 测试使用 marker + `require_path` / `require_main_db_cert_counts` / `skip_outdated_freeze`。
3. **canary 014**：恢复单测不再硬编码主库 (55,2)；仅断言测试前后指纹不变；认证计数留在专用 `test_10_*`。
4. **phase_1b3**：补 `sys.path`；无 27B 时显式 integration skip。
5. **前端空状态**：Inspector 默认折叠（curve-first）后，测试需展开再断言 `journey-detail-empty`；保留空状态文案与 DOM。

## 4. 仍需外部条件的测试

| Marker | 前置条件 |
|--------|----------|
| `requires_cloud_pricing` | 或由 fixture 安装；真机需从 `config/cloud_pricing.example.json` 复制并验证 |
| `requires_audit_assets` | `audits/single-chapter-pipeline/real-canary-v*` 捕获与报告 |
| `requires_main_db_snapshot` | `data/storylens.db` 认证快照（55/2） |
| `requires_certification_artifacts` | `artifacts/single-chapter-pipeline-certification/` |
| `freeze_baseline` | 对当前树重新 seal 后的 freeze / thaw / UI freeze 清单 |
| `canary_offline` | 与上列审计捕获一并使用 |
| `integration` | 本机已注册 27B 等本地模型 |

运行可选组示例：

```powershell
.\.venv\Scripts\pytest.exe apps/api/tests -q -m "requires_audit_assets or freeze_baseline"
```

排除可选组（仅核心，若需强制）：

```powershell
.\.venv\Scripts\pytest.exe apps/api/tests -q -m "not (requires_audit_assets or requires_main_db_snapshot or requires_certification_artifacts or freeze_baseline or canary_offline or integration)"
```

首发默认仍建议跑 **全量** `pytest apps/api/tests -q`：缺资产项应显示为 skipped，而非 failed。

## 5. 首发必须通过的测试集合

以下核心路径在无认证 DB / 无 canary 捕获时也必须 **通过**（不得 skip 掩盖）：

- 小说导入、章节/段落解析
- Provider 配置与凭据（Fake / 配置写入）
- AnalysisRun 创建、场景边界、边界审核
- Scene Analysis（单元 / Fake Provider）
- Reader Journey 引擎与桌面 Vitest（含空状态）
- resume / recovery（含 `phase_1c_a7` recover，依赖定价 fixture）
- 本地数据路径、sidecar health
- Provider 连接测试（`phase_1c_a6`，依赖定价 fixture）

## 7. 当前是否建议发布

| 项 | 结论 |
|----|------|
| 自动化核心路径 | 在定价 fixture + 可选资产门控落地后，应达到「全量 pytest 无失败、Vitest 全绿」 |
| 人工验收 | 仍须完成 `docs/v0.1.0-preview-acceptance.md`（安装、向导、隐私、VIP 文案等） |
| Freeze seal | 当前树相对历史 freeze **有意漂移**；不阻断 Preview，但正式 RC 前需 re-seal |
| 真实 Canary | 需操作者授权与审计资产；非 Preview 默认阻断项 |
| **是否建议发布 v0.1.0 Preview** | **建议**：在本节完整命令全部实际跑通、且人工清单关键项勾选后发布；**不**建议在未跑 smoke / 未配置本机 `cloud_pricing.json` 的真机上宣称「已验证云端计费」 |
