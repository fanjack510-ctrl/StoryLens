## 9. P0-01：普通 AI 配置未写入真实 Provider / Credential 链路

**状态：已修复（发布阻断已解除，待本机完整复验）**

### 根因

1. **首次向导「下一步」不保存**：`FirstLaunchWizard` 仅「测试连接」调用保存逻辑，「下一步」直接进入第 3 步，用户可在未写入 CredentialStore / ProviderConfiguration 的情况下完成向导。
2. **前端把 GET 配置整包回传 PUT**：`saveAiServiceConfiguration` 展开 `ProviderConfigurationResponse`，其中 `base_url: ""` 无法通过 `HttpUrl` 校验（422），导致普通设置/向导首次保存失败；开发者高级页手工填写 Base URL 后反而能成功——形成「必须进开发者模式」的假象。
3. **状态口径不一致**：普通设置用 `connection_state` / 传输诊断成功文案显示「已连接」，分析对话框按 `manual_boundary_candidate_eligible` 过滤 Provider。云端总开关关闭、未 bootstrap endpoint、eligibility blockers 存在时，会出现「设置页已连接 / 分析页无 Provider」。
4. **多步非原子 API**：预算、Provider、云端开关、enable/connect 分次调用，部分成功即可造成普通页与高级页状态分叉。

### 修改方案

- 新增后端原子接口：
  - `GET/POST /api/v1/desktop/ai-setup/recommended-qwen`
  - `POST /api/v1/desktop/ai-setup/recommended-qwen/repair`
- 服务实现：`apps/api/app/services/recommended_ai_setup.py`（测试连接、CredentialStore、唯一 `aliyun_qwen_plus`、模型映射、云端开关、eligibility）。
- 前端统一入口：`configureRecommendedQwenService` / `fetchRecommendedQwenStatus`（向导与 `SettingsAiServiceTab` 共用）。
- 向导：测试=`persist:false`；下一步=`persist:true` 且 `provider_eligible` 才进入完成步。
- 设置页：以 `provider_eligible` 作为「可以开始分析」唯一绿灯。
- 分析对话框：自动选中唯一可用 Provider；无可用时给出中文原因 +「去配置 AI 服务」。
- 兼容：`ProviderConfigurationUpdate` 将空 `base_url` 视为 `None`；PUT 后 bootstrap 补齐公共百炼 endpoint。

### 人工复验步骤

1. 清空或使用新用户数据目录，启动 Preview 构建。
2. 首次向导：填写百炼 API Key →「测试连接」应提示成功但**未保存** → 勾选正文同意 →「下一步」应提示保存成功。
3. 重启应用：设置 · AI 服务应显示凭据已配置、云端已开启、可用于分析=是（无需开发者模式）。
4. 打开章节 → 开始分析：普通模式无 Provider 下拉框，已自动使用 `aliyun_qwen_plus`，可勾选同意后创建任务。
5. 开发者高级页修改后返回普通 AI 页：状态应与后端一致。
6. 旧配置（有 Key、Provider 启用、云端关闭）：在设置勾选正文同意后点「修复配置」，应补齐云端开关且不删除凭据。
