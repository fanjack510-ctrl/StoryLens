# 拆文引擎设计（B）

诊断回答「我这本哪里有毛病」。拆文回答「这本为什么爆，我能学什么」。
两者读同一份快照、共用同一套 L1 抽取，其余部分没有一处相同。

参照样本：《一梦》拆文（外部材料，2026-08-17 收到）。下文凡说「样本」即指它。

---

## 0. 三条硬约束

这三条是从评测那边的教训直接来的，写死在这里是为了防止拆文慢慢长回一份体检报告。

**INV-B1 不出现任何数字评分。**
没有分数、没有百分位、没有评级、没有图表、没有热力。样本通篇零个数字，而
它比我们的报告更有用。一旦某个板块想放数字，说明那条结论没能用文字讲清楚——
该修的是那条结论。

**INV-B2 每一条结论都要能引出原文。**
爆点、钩子、可复用点都挂 `evidence_id`，点开看到的是小说原句。样本里每一个
爆点都能翻到那一页，这是它和「读后感」的分界线。
证据索引现有 419 条真实原句（中位数 30 字），这一条的数据基础已经存在。

**INV-B3 爆点是选出来的，不是均摊的。**
允许十条全部落在同几章。任何「每阶段一条」「每 N 章一条」的名额分配都是错的。
这一条有直接的反面教材：评测的「重大转折」按阶段均摊，专业读者一眼就说「不对」。
**用结构位置代替重要性判断，是评测那份报告最深的一个错误，拆文不得重犯。**

## 1. 产出物

六个板块，对着样本的结构。

| # | 板块 | 每条包含 | 来源 |
|---|---|---|---|
| 1 | 起承转合 | 标题（一句话情节）+ 情节段 + 章号范围 | U1 |
| 2 | 爆点清单 | 标题（具体到一句话/一个动作）+ **原文引用** + 为什么打动人 + 章号 | U2 |
| 3 | 逐章钩子 | 该章末尾留给读者的问题，**原话疑问句** | L1 增量 |
| 4 | 可复用点 | 这个写法是什么 + 为什么有效 + 可迁移到什么场景 | U4 |
| 5 | 配角功能 | 他在这本书里承担什么任务，有没有越界抢戏 | U3 |
| 6 | 分章拆解 | 梗概 + 为什么这样写 + 钩子 | L1 增量 + 现有章节功能 |

**起承转合恰好四段**，不是 N 个。它是叙事功能上的切分，不是把书按分区数除开——
样本的四段是「起：自卖为婢入温家…」这种，标题本身就是情节。

**爆点的标题必须具体到可引用的东西。** 样本的十条里有四条直接就是一句台词。
「第三幕情绪高点」不是爆点，「宝银说"取舍之间也是风骨"」才是。

**「为什么打动人」答的是机制，不是强度。** 样本对一句问话的解释是「身份倒转：
一个二品尚书问一个当过丫头的人"你是不是嫌我脏"」——这是可以学走的写法。
「这里情绪值 90」不是。

## 2. 数据从哪来

### 已经有的

- `evidence_index`：419 条真实原句，带 `chapter_index` 和偏移 → 爆点的引文
- `events` / `chapter_signals` / 实体 / 关系 → 情节骨架
- `HOOK_VOCABULARY`（按类型的钩子词表，已按五轴画像分好）→ 爆点的类型词汇。
  言情的爆点和升级流的爆点不是一回事，这套词表已经建好了，直接复用。

### 要新抽的（L1 增量，additive，遵守 INV-P1）

一个新的 profile delta，`story_breakdown`，与画像无关、由分析模式开启：

```
chapter_signals[].end_hook_question   该章末尾留给读者的问题，原话疑问句，≤30 字
                                       没有钩子就留空，不要编
chapter_signals[].craft_note          这一章为什么这样写，≤40 字（可选，见 §7c）

standout_moments[]                    每块最多 3 条候选爆点
  chapter_ref
  quote        正文原句，必须原样出现在本块正文中
  why          为什么这一处会打动读者，≤50 字
  evidence     段落引用
```

`quote` 必须原样出现在正文里——这一条要走和 `mentions.surface_norm` 同一套校验，
否则模型会写出「像原文的句子」，而那正是拆文最不能出的错。

代价：每块输出多约 500 token。11 块 ≈ +5,500 输出 ≈ +¥0.01。

### 明确不做的（v1）

- **全书唯一性判断**（样本里「这是她全书唯一一次哭」）。这是否定性统计——要证明
  别处都没有——而引擎只做正向计数。U2 会拿到完整候选列表，模型**有机会**说出来，
  但不保证，也不校验。
- **跨章重复的梗**（样本里「狗蛋」这个谎言在三处被重复问起）。v1 由 U4 顺带识别，
  不单独抽取。要做对需要表层字符串的跨章追踪，是独立一期的事。

## 3. 调用图

```
L1 抽取（11 块，与诊断共用，带拆文增量）
        │
        ├─ U1 起承转合    ← 阶段摘要 + 时间线脊柱（抽样 ≤60 条）+ 画像
        ├─ U2 爆点选择    ← 全部候选爆点（去重后 ≤120 条，每条带原文）+ 类型钩子词表
        └─ U3 配角功能    ← 人物表（≤24 人，各带 key_events 与对主角关系）
                │
                └─ U4 可复用点  ← U1 + U2 + U3 的结果
```

U1/U2/U3 互不依赖，U4 依赖全部三个。所以是两轮，四次调用。

每个单元的输入都由固定上限决定，与书长无关——和现有的有界单元一套规矩。

**U2 是这个引擎的核心，也是唯一一个不能出错的地方。** 它拿到的是全书候选（每条带
原文），要做的是「选出最动人的 8–12 个瞬间并解释机制」。它不得按章号分配名额
（INV-B3），提示词里要把这一点写成禁令而不是建议。

## 4. 成本

拆文模式跳过诊断的主题投影、评估、节奏曲线、悬念配对。

《系统豪横》84 章 / 195,269 字，用已拟合的三本书模型算：

| | 调用 | 输入 | 输出 | 花费 |
|---|---|---|---|---|
| 诊断（现状） | 24 | 210,225 | 44,524 | ¥0.30 |
| 拆文（独立跑） | 15 | 184,428 | 41,511 | ¥0.26 |
| **拆文（复用已有 L1）** | **4** | **11,680** | **2,452** | **≈¥0.01** |

**这是最重要的一行**：L1 与诊断共用，所以一本已经跑过诊断的书，拆文只要四次
有界调用，几乎免费。反过来也成立。

代价是两个模式的 L1 必须带同一套增量（否则复用不了缓存），也就是诊断模式也会
多花那 ¥0.01。值得。

## 5. 契约

`WholeBookAnalysisV2` 增加一个可选顶层节。全部字段可选，所以已存的文档照常通过校验。

```python
class StoryBeat(Ranged):        beat: Literal["起","承","转","合"]; title: str; summary: str; evidence: list[str]
class StandoutMoment(M):        rank: int; title: str; quote: str; why_it_lands: str; chapter: int; evidence: list[str]
class ChapterHook(M):           chapter: int; question: str; evidence: list[str]
class ReusableTechnique(M):     name: str; what_it_is: str; why_it_works: str; transfers_to: str
class CastFunction(M):          name: str; function: str; stays_in_lane: bool; evidence: list[str]

class StoryBreakdownResult(M):
    version: str = "1.0"
    availability: Availability
    four_beats: list[StoryBeat]
    standout_moments: list[StandoutMoment]
    chapter_hooks: list[ChapterHook]
    reusable_techniques: list[ReusableTechnique]
    supporting_cast: list[CastFunction]
```

注意 `StandoutMoment.quote` 是**存下来的原文**，不是引用 id。引文短（中位数 30 字），
存一份让报告自包含、导出后仍可读，比让导出去查索引可靠。`evidence` 仍然给，
用来跳回原文位置。

## 6. 界面

同一本书，两个按钮：**诊断** 和 **拆文**。不是一个报告的两个 tab——它们回答的问题
不同，用户来的时候心里想的也不是同一件事（诊断看自己的书，拆文看别人的书）。

拆文页：**爆点是第一屏**，因为那是用户来看的东西。其后依次起承转合、可复用点、
配角功能、分章拆解。零图表。

## 7. 需要定的三件事

**a) 拆文是独立入口，还是全书报告里的一个 tab？**
我倾向独立入口，理由见 §6。但如果用户主要还是分析自己的书，做成 tab 更省事。

**b) 爆点数量固定十条，还是让引擎自己定 8–12？**
样本是十条。固定数量的好处是可比；坏处是短书凑数、长书砍掉真爆点。
我倾向让引擎在 8–12 之间自己定，并且**要求它说明为什么是这个数**。

**c) 逐章批注要不要做？**
样本每章都有一段红字批注解释心理。做法是 L1 增量加 `craft_note`，代价约
84 × 30 token ≈ +2,500 输出 ≈ +¥0.005，很便宜。
但质量存疑：≤40 字的批注很容易退化成复述梗概。建议**先不做**，等爆点这条
路径验证过质量再说——爆点和批注是同一种能力，爆点做不好，批注一定更差。

---

## 8. 验证方式

不用测试样例验证，用《一梦》验证：**拿样本那本书跑一遍，看引擎选出的十个爆点和
人写的十个重合几个。** 重合 6 条以上算这条路走通了；低于 4 条说明「什么叫动人」
这件事模型判不了，整个方向要重估。

这个判据要在写代码之前定死，否则跑完之后一定会有人（包括我）找理由说结果还行。
